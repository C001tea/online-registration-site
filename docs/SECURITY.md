# Безопасность

Что защищено, как и что проверять. Обновлять при изменениях.

## Доступ и роли
- Панель салона: владелец, админ, мастер; права проверяются на сервере в каждом запросе
  (`dashboard/permissions.py`). Данные каждого салона видны только его сотрудникам —
  это покрыто тестами (запросы к чужому салону дают 404).
- Пароли — хеш PBKDF2 (Django), открытым текстом нигде не хранятся. Правила: не короче 8
  символов, не только цифры, не популярный, не похож на логин — для персонала и клиентов.
- Перебор паролей: 5 неудачных попыток за 15 минут на аккаунт — блокировка (сайт, панель,
  админка Django). Код из Telegram — 5 попыток.
- Токены входа (JWT): клиенты — access 1 час (сайт сам обновляет), refresh 30 дней;
  персонал — 12 часов / 7 дней. После смены пароля старые токены персонала не действуют.
  Токен персонала нельзя обновить через вход клиента.
- Встроенная админка Django: путь задаётся в `.env` (`DJANGO_ADMIN_PATH`), рекомендуется
  нестандартный; вход с лимитом перебора.

## Защита от спама и злоупотреблений
- Онлайн-запись: поле-ловушка для ботов; не больше 30 попыток в час с IP, 10 — на номер,
  300 — на салон; не больше 3 предстоящих онлайн-записей на номер.
- Регистрация: не больше 10 аккаунтов в час с IP. Вход через Telegram: 20 в час с IP.
- Поиск клиента по номеру в панели: 120 запросов в час на сотрудника.
- Счётчики лимитов — в базе (общие для всех процессов, не сбрасываются при деплое).
- IP посетителя: сайт ходит в API через Vercel, адрес клиента приходит в `X-Real-IP`
  (проверка: `GET /api/health/?ip=1` показывает ваш IP).

## Данные
- Персональные данные: имя, телефон, email (необязательно), история визитов. Согласие при
  записи сохраняется с датой. Политика конфиденциальности — `/privacy`.
- В Telegram и в логи GitHub Actions имена и телефоны клиентов не попадают (кроме сообщений
  салону о его же записях).
- Резервные копии: ежедневно, на сервере 14 последних + зашифрованная (AES-256) копия в
  GitHub на 30 дней; раз в неделю автоматически проверяется восстановление.
- Фото: проверка формата и размера, удаление EXIF (геолокации) перед сохранением.

## Сервер и сеть
- Только HTTPS (Let's Encrypt, Caddy), HSTS. Заголовки: `X-Frame-Options: DENY`,
  `nosniff`, CSP `frame-ancestors 'none'`, `Permissions-Policy`; на сайте — CSP (vercel.json).
- Наружу открыты только 80/443 (Caddy) и SSH (только по ключу). База и Django наружу не
  открыты — только внутри Docker.
- Telegram-вебхук принимает только запросы с секретным заголовком.
- Секреты (ключи, пароли) — только в `.env` на сервере и в секретах GitHub; в репозитории их
  нет (проверено по всей истории).
- Зависимости проверяются `pip-audit` и `npm audit`; известные уязвимости закрыты обновлением.
- Проверка сервера: Actions → **Security status** (раз в неделю и вручную) — вход по SSH
  только по ключу, автообновления безопасности, открытые порты.

## Что остаётся на стороне владельца
- Длинные уникальные пароли для панели, свои у каждого сотрудника; уволился — «Закрыть
  доступ» в карточке мастера.
- Не пересылать никому ссылку для подключения Telegram к панели и код входа.
- Включить Sentry (ошибки приходят сразу).
- Двухфакторная защита аккаунтов GitHub, Vercel, Oracle, Namecheap, Cloudinary, Telegram —
  через них можно получить доступ ко всему.
