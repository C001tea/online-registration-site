# TimePoint — контекст проекта (памятка для новой сессии)

Онлайн-запись клиентов для салонов и студий в Молдове (SaaS). Владелец проекта пишет по-русски:
**отвечай только по-русски, действуй самостоятельно, не засыпай вопросами.** Пароли и ключи в чат
не просить: секреты — только через GitHub Secrets / формы.

## Репозитории и адреса
| Что | Где |
|---|---|
| Бэкенд (Django + DRF, Postgres) | github.com/C001tea/online-registration-site |
| Фронтенд (React + Vite + Tailwind) | github.com/NichitaOrmanji/nail-salon-frontend |
| Сайт | https://nail-salon-frontend.vercel.app (Vercel; `vercel.json` проксирует `/api` на api.timepoint.tech) |
| API | https://api.timepoint.tech (сервер Oracle, Docker, Caddy; деплой — GitHub Actions) |
| Лендинг | `/welcome` (на `timepoint.tech` и `www` станет главной) |
| Регистрация салона / вход | `/admin-panel/signup`, `/admin-panel/login` |
| Домен | timepoint.tech (Namecheap); `*.timepoint.tech` для салонов в Vercel ещё НЕ подключён |

Адрес салона: `?salon=<slug>` или поддомен `<slug>.timepoint.tech`; салон по умолчанию — `jcnails`.

## Как устроено
- **Деплой бэкенда:** push в `main` → тесты + e2e → деплой (`deploy.yml`, есть ручной запуск).
  Несекретные настройки сервера меняются без SSH: Actions → **Server settings**. Пароль почты —
  секрет `EMAIL_HOST_PASSWORD`, попадает на сервер при деплое.
- **Фронтенд:** merge в `main` → Vercel деплоит сам. Откат: Vercel → Deployments → Promote.
- **Тесты:** бэкенд — `python manage.py test` (в CI Postgres; локально можно `DATABASE_URL=sqlite:///...`).
  Сквозные — Playwright в `frontend/e2e` (`e2e/README.md`): нужен бэкенд с салоном `e2e`
  (`manage.py e2e_seed`) и сборка `VITE_DEFAULT_SALON=e2e`. Фронтенд-workflow `e2e.yml` вызывается из CI бэкенда.
  Падает e2e = что-то сломано; не отключать и не пропускать тесты.
- **Безопасность сайта:** жёсткий CSP в `vercel.json` (шрифты и скрипты — только свои); шрифты ставим через `@fontsource`.
- Документация бэкенда: `docs/` (OPERATIONS, SECURITY, SIGNUP, STAFF, NEW_SALON, HTTPS).

## Что готово (на проде)
Запись клиента (RU/RO), журнал по неделе, панель (услуги, мастера, графики, клиенты, чёрный список со штрафом,
должники, касса и зарплаты, роли владелец/администратор/мастер), Telegram-бот и вход клиента, автоподтверждение,
удаление данных клиента, фото, правила и политика, Sentry, бэкапы с проверкой восстановления, uptime.
**Самостоятельная регистрация салона** (включена): лендинг → форма → салон скрыт до подтверждения email →
«Начало работы» (чек-лист, ссылка, QR) → 14 дней пробного периода; «Забыли пароль?» по email.
Почта: Brevo, домен timepoint.tech подтверждён (SPF/DKIM/DMARC), письма доходят во «Входящие».
Лендинг: светлая (rose-600) и тёмная (rose-500) темы, шрифты Plus Jakarta Sans + Instrument Serif
(кириллица из Manrope/Playfair), логотип «дуга и точка» (вариант J) — пока только на лендинге.
Аудит безопасности и UX выполнен, исправления смёржены (общие лимиты регистраций, очистка названия салона,
длинные названия на телефоне, Promise.allSettled для слотов).
Dependabot + `npm audit`/`pip-audit` в CI.

## Решения и ограничения (важно)
- Новая тема интерфейса «Море» владельцу **не понравилась** и откатана; код в ветке `feature/theme-sea` (frontend),
  `backup/before-sea-theme` — main до неё. Не возвращать без прямой просьбы.
- Дизайн лендинга утверждён: светлая и тёмная темы, акцент rose; без «AI-градиентов», без нумерации 01/02/03.
- Демо-данные — только в демо-салоне (workflow Demo salon); на старом сервере чужой проект (`pdf_to_word`) не трогать.
- Репозиторий публичный: личные данные и секреты не попадают в логи Actions.
- Владелец говорил «да, мёржи сам»: PR можно мёржить после зелёного CI. Коммиты — на русском, с трейлером
  `Co-Authored-By` и ссылкой на сессию, если её дают; в PR/коммитах нет названий моделей.
- Без прямой просьбы не создавать лишних PR и не запускать разрушающие workflow.

## Подводные камни
- `pkill -f "<часть команды>"` убивает собственную оболочку — останавливать процессы через `/proc/*/cmdline`.
- e2e на медленном CI бывает хрупким: вводить в поле после `toHaveURL`/`networkidle`, не плодить `sleep`.
- Playwright в облачной среде: браузер `/opt/pw-browsers/chromium` (`PW_CHROMIUM_PATH`); локально у владельца — стандартный `npx playwright install`.
- На сервере Django `DEBUG` выключен; регистрация работает только с настроенной почтой (`EMAIL_CONFIGURED`).
- Лимиты: регистрации 5/ч на IP и 30/ч общий, сброс пароля 10/ч на IP, 3/ч на адрес и 60/ч общий.
